# はじめに
AtCoderで使われているdcは`GNU dc 1.5.2`です。以前のAtCoderでは`GNU dc 1.4.1`が使われていましたが、この2つはいくつかのコマンドの細かい挙動が違います。
そのため、以前ACしたコードが、今のAtCoderでは違う出力になることがあります。この記事では、競技プログラミングで影響がありそうな違いをまとめます。

dcの使い方については連載「競技プログラミングでdcを使う」を見てください。

[1](https://qiita.com/shogo314/items/abdf5e8e9e213bafe837) [2](https://qiita.com/shogo314/items/059094162959029cce3e) [3](https://qiita.com/shogo314/items/6838b0beb84f911f0515) [4](https://qiita.com/shogo314/items/a7b6668602bb976ef940) [5](https://qiita.com/shogo314/items/2c48e1db9574ef0c61a6) [6](https://qiita.com/shogo314/items/b3995de81116b7ca5465) [7](https://qiita.com/shogo314/items/23ac5a98e316802bed87) [まとめ](https://qiita.com/shogo314/items/fff4be1573d2f86dba2a)

以下の出力はすべて、2つのバージョンで実際に実行して確かめたものです。エラーメッセージや警告は標準エラー出力に出るので、表の「出力」には含めていません。AtCoderでは標準エラー出力は採点されません。

# 入力の終わりで「?」を実行したとき
入力をすべて読み終わった後に「?」を実行すると、1.4.1では何も積まずに次のコマンドへ進みますが、1.5.2ではその場でプログラムが終了します。

```
??+p
```

|入力|1 2|
|:-:|:-|

|バージョン|出力|
|:-:|:-|
|1.4.1|3|
|1.5.2|(なし)|

「?」は1行をまとめて読むので、最初の「?」で1と2が積まれます。1.4.1では2つ目の「?」は何もせず、「+p」で3が出力されます。1.5.2では2つ目の「?」で終了するので、何も出力されません。

入力の行数より多く「?」を書いたコードは、1.5.2では答えを出力する前に終了してしまいます。「?」は入力の行数と同じ回数だけ使うようにしましょう。

# 比較がエラーになったとき
スタックの値が足りないときや、比べる値が文字列のときは、比較のコマンドはエラーになります。このとき1.4.1では、「=」「!<」「!>」の3つだけが*x*を実行してしまいます。1.5.2ではどの比較でも*x*を実行しません。

```
[[yes]p]sa1=a
```

|バージョン|出力|
|:-:|:-|
|1.4.1|yes|
|1.5.2|(なし)|

スタックに1しかないので「=a」はエラーになりますが、1.4.1ではaが実行されてyesが出力されます。「<」「>」「!=」は、どちらのバージョンでもエラーのときは*x*を実行しません。

# 小数を指数にしたとき
「^」の指数に小数を渡すと、1.4.1では小数部分を捨てて計算します（警告が出ます）。1.5.2でも、指数の絶対値が1以上なら同じように小数部分を捨てて計算しますが、`.5`のように整数部分が0の小数だとエラーになり、スタックはそのまま残ります。

```
2 .5^p
```

|バージョン|出力|
|:-:|:-|
|1.4.1|1|
|1.5.2|.5|

1.4.1では指数が0として扱われて$2^0=1$になります。1.5.2ではエラーになり、2と.5が残るので、一番上の.5が出力されます。

```
2 1.5^p
```

|バージョン|出力|
|:-:|:-|
|1.4.1|2|
|1.5.2|2|

この場合はどちらも指数を1として計算します。

実際の問題では、[ABC096](https://atcoder.jp/contests/abc096/tasks/abc096_a)の次のコードが、1.4.1では正しく動きますが、1.5.2では$a \gt b$のときに間違えます。

```
?kdKr/0r^-p
```

|入力|2 1|
|:-:|:-|

|バージョン|出力|
|:-:|:-|
|1.4.1|1|
|1.5.2|-.5|

「k」で小数点以下の桁数を設定しているので、$b \div a$が.5のような小数になり、それを指数にしているのが原因です。1.5.2では、桁数を変えずに整数のまま割り算をする`?sbdlbr/0r^-p`のように書けば正しく動きます。

# エラーのときに取り出した値
1.5.2では、エラーになったコマンドが取り出した値はスタックに戻されます。1.4.1でも、「+」「/」「%」のように2つの値を取り出す計算のコマンドは値を戻しますが、次のようなコマンドではエラーのときに値が消えてしまいます。

|コマンド|エラーになる例|
|:-:|:-|
|v|負の数の平方根|
|k|負の数を桁数に設定|
|i, o|使えない基数を設定|
|R|文字列を渡す|
|Q|負の数を渡す|
|:*x*|負の数を添字にする|

```
5 _1v f
```

|バージョン|出力|
|:-:|:-|
|1.4.1|5|
|1.5.2|-1<br>5|

1.4.1では-1が消えて5だけが残り、1.5.2では-1も残ります。

実際の問題では、[ABC092](https://atcoder.jp/contests/abc092/tasks/abc092_a)の次のコードが、1.4.1では正しく動きますが、1.5.2では間違えます。

```
[x?d?-kK-0k]dx+p
```

|入力|600<br>300<br>220<br>420|
|:-:|:-|

|バージョン|出力|
|:-:|:-|
|1.4.1|520|
|1.5.2|20|

「?d?-k」で$A-B$を桁数に設定し、「K-」で$A$から引いて$A,B$の小さい方を求めています。$A \lt B$のときは「k」がエラーになりますが、1.4.1では$A-B$が消えて桁数は0のままなので、「K-」で$A$が残ります。1.5.2では$A-B$がスタックに残るので、計算がずれてしまいます。

[ABC078](https://atcoder.jp/contests/abc078/tasks/abc078_a)の次のコードも、1.4.1では正しく動きますが、1.5.2では間違えます。

```
_1?-dvv61+P
```

|入力|A C|
|:-:|:-|

|バージョン|出力|
|:-:|:-|
|1.4.1|<|
|1.5.2|;|

<、=、>の文字コードは60、61、62です。$X-Y$が正なら「vv」で4乗根の整数部分の1になり、0なら0のままなので、61を足して>か=を出力します。
$X-Y$が負のときは「v」がエラーになります。1.4.1では2回のエラーで$X-Y$が2つとも消え、最初に積んだ-1に61が足されて<が出力されます。1.5.2では$X-Y$が残るので、$61+(X-Y)$の文字が出力されます。

[ABC065](https://atcoder.jp/contests/abc065/tasks/abc065_a)の次のコードも同じです。

```
[dangerous][safe][delicious]?-d3R+vrv3Rp
```

|入力|4 3 6|
|:-:|:-|

|バージョン|出力|
|:-:|:-|
|1.4.1|safe|
|1.5.2|delicious|

$A-B$と$A-B+X$の平方根を計算し、1.4.1では負の数の平方根がエラーで消えることを使って、残った数の個数（2個、1個、0個）で「3R」が持ってくる文字列を変えています。1.5.2では数が消えないので、いつもdeliciousが一番上に来てしまいます。

# 「a」の警告
1.5.2では「a」は非推奨になり、使うと警告が出ます。ただし警告は標準エラー出力に出るだけで、出力される内容は1.4.1と同じです。AtCoderでは標準エラー出力は採点されないので、提出には影響しません。

```
65a p
```

|バージョン|出力|
|:-:|:-|
|1.4.1|A|
|1.5.2|A|

# 変わっていないこと
次のような挙動は、どちらのバージョンでも同じです。

- 「?」で`-3`を読むと、「-」が引き算として扱われてエラーになり、3だけが積まれます。負の数を入力するときは`_3`のように書く必要がありますが、AtCoderの入力では`-`が使われます。
- 「R」にデータの数より大きい数を渡すと、データの数を渡したときと同じふるまいをします。0を渡すと何もしません。
- $0^0$は1になります。

# おわりに
1.4.1で書かれた過去のコードを1.5.2で動かすときは、特に「?」の回数と、エラーになる比較に気を付けてください。
