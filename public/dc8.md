# はじめに
前回はマクロで繰り返しを書きました。最終回の今回は、入力に文字や記号、負の数が含まれる問題を扱います。dcには文字列を読み込むコマンドがないので、多くの問題は解けません。それでも、「?」の仕組みをうまく使うと解ける問題があります。

# 入力はコードとして実行される
これまで「?」は数を読み込むコマンドとして使ってきましたが、正確には「入力を1行読み込んで、それをコードとして実行する」コマンドです。数字を読み込むと数が積まれるのは、コードとして数を書いたのと同じだからです。
そのため、入力に文字や記号が含まれていると、それがコマンドとして実行されます。英字を1文字だけ読み込んだときのふるまいは、次のように分けられます。

|文字|ふるまい|
|:-|:-|
|A〜F|10〜15の数として積まれる|
|a c d f i k l n o p q r s v x z<br>I K L O P Q R S X Z|コマンドとして実行される|
|上記以外|何も起こらない（エラーメッセージが出るだけ）|

例えば`d`を読み込むと一番上の値が複製され、`c`を読み込むとスタックが空になります。何も起こらない文字どうしは区別できないので、例えば[ABC049](https://atcoder.jp/contests/abc049/tasks/abc049_a)では、母音の`e`と子音の`b`が同じふるまいになり、正しく判定できません。
文字列をそのまま出力したり、何文字目かを調べたりする問題も同じ理由で解けません。ここでは、文字のふるまいの違いで答えが決まる問題を見ていきます。

# 文字を読み込む
[ABC056](https://atcoder.jp/contests/abc056/tasks/abc056_a)

```
?z1+2%4*68+P
```

|入力|D H|
|:-|:-|

|出力|D|
|:-:|:-|

![a056_01.png](https://raw.githubusercontent.com/shogo314/qiita/main/images/dc8/a056_01.png)

`H`は何も起こらない文字で、`D`は13として積まれます。そのため「?」のあとのデータの数は、入力に含まれる`D`の数になります。答えは`D`が偶数個（0個か2個）ならH、1個ならDです。
「z1+2%」で、`D`が偶数個なら1、奇数個なら0を求めます。HとDの文字コードは72と68なので、「4\*68+」で72か68にして、「P」で文字として出力します。

***

[ABC095](https://atcoder.jp/contests/abc095/tasks/abc095_a)

```
Add?zA0*A00r-p
```

|入力|oxo|
|:-:|:-|

|出力|900|
|:-:|:-|

![a095_01.png](https://raw.githubusercontent.com/shogo314/qiita/main/images/dc8/a095_01.png)

`o`は一番上の数を取り出して出力の基数にするコマンドで、`x`は一番上の数をそのまま積み直すので何も起こりません。そこで先に「Add」で10を3つ積んでおきます。`o`を読むたびに10が1つ取り出されます（基数は10のままなので出力には影響しません）。
残った10の数は`x`の数なので、「z」でそれを求めます。値段は$1000-100 \times (xの数)$です。「A0」は$10 \times 10 + 0=100$、「A00」は1000です。
「AAA」と書くと$10 \times 100+10 \times 10+10=1110$という1つの数になってしまうので、「Add」で複製しています。

***

[ABC085](https://atcoder.jp/contests/abc085/tasks/abc085_a)

```
[2018/01/]n?A~rnp
```

|入力|2017/01/07|
|:-:|:-|

|出力|2018/01/07|
|:-:|:-|

「n」は一番上の値を改行せずに出力して取り出すコマンドです。最初に「2018/01/」を出力しておきます。
入力をコードとして実行すると、2017が積まれ、「/」はデータが1つしかないのでエラーになります。次に1が積まれ、「/」で$2017 \div 1=2017$になり、最後に7が積まれます。つまり日が一番上に来ます。
日を「A~」で十の位と一の位に分け、「rn」で十の位を、「p」で一の位を出力します。こうすると、07のように0を付けて出力できます。

***

[ABC050](https://atcoder.jp/contests/abc050/tasks/abc050_a)

```
0?rdsS+lS*lSd*v/p
```

|入力|5 - 7|
|:-:|:-|

|出力|-2|
|:-:|:-|

![a050_01.png](https://raw.githubusercontent.com/shogo314/qiita/main/images/dc8/a050_01.png)

入力の`+`や`-`もコマンドとして実行されますが、入力をそのまま「?」で読むと、記号の時点ではデータが$A$の1つしかないのでエラーになってしまいます。そこで先に0を積んでおきます。
`+`のときは$0+A=A$、`-`のときは$0-A=-A$になってから$B$が積まれます。このときの2つの数を$s,B$とすると、`+`なら$s+B=A+B$、`-`なら$s+B=B-A$で、答えはその$-1$倍になります。$A \geqq 1$なので、$s$の符号で区別できます。
「rdsS+」で$s$をメモリSに入れて$s+B$を計算し、「lS\*lSd\*v/」で$s$を掛けて$|s|=\sqrt{s^2}$で割ります。$s$の符号を掛けたことになります。

# 負の数を読み込む
AtCoderの入力では負の数は`-2`のように書かれますが、dcでは負の数は`_2`と書くので、`-`は引き算のコマンドとして実行されます。[前回のABC022](https://qiita.com/shogo314/items/23ac5a98e316802bed87)では、1行に1つの数を読み込むときにこれを利用しました。1行に複数の数があると、もっと複雑になります。

[ABC098](https://atcoder.jp/contests/abc098/tasks/abc098_a)

```
[r]sa0d?z_1r^sEsTsSlSlE*lT+lSd*vlE*lT*d3Rd3R>ap
```

|入力|3 -2|
|:-:|:-|

|出力|6|
|:-:|:-|

「0d」で0を2つ積んでから読み込みます。$A,B$の大きさを$a,b$とすると、符号によってスタックは次のようになります。

|入力|スタック（下から）|データの数|
|:-:|:-|:-:|
|$a$ $b$|$0,0,a,b$|4|
|$-a$ $b$|$0,a,b$|3|
|$a$ $-b$|$0,-a,b$|3|
|$-a$ $-b$|$-a,b$|2|

`-3 2`のとき

![a098_01.png](https://raw.githubusercontent.com/shogo314/qiita/main/images/dc8/a098_01.png)

`3 -2`のとき

![a098_02.png](https://raw.githubusercontent.com/shogo314/qiita/main/images/dc8/a098_02.png)

上から2番目を$s$、一番上を$t$とします。$t$はいつも$b=|B|$です。データの数が偶数のときは$A=s$、奇数のときは$A=-s$になります。データの数を$d$として$e=(-1)^d$とおくと、$A=es$です。

答えの$\max(A+B,A-B,AB)$は、$A+B$と$A-B$の大きい方が$A+|B|$なので、$\max(A+|B|,AB)$です。表の4通りを調べると、$AB=e|s|t$になっています。

- 「z\_1r^sE」で$e=(-1)^d$をメモリEに入れ、「sTsS」で$t,s$をメモリT、Sに入れます。
- 「lSlE\*lT+」で$A+|B|=es+t$を計算します。
- 「lSd\*vlE\*lT\*」で$AB=e|s|t$を計算します。
- 「d3Rd3R>a」で大きい方を一番上にして出力します。aは2つを入れ替えるマクロです。

メモリの名前は、$s,t,e$の頭文字にしています。

## 解けない問題
[ABC061](https://atcoder.jp/contests/abc061/tasks/abc061_a)と[ABC075](https://atcoder.jp/contests/abc075/tasks/abc075_a)は、1行に3つの数があり、負の数を含みます。この2問は、dcでは解けません。
例えばABC061の次の2つの入力は、最初に何を積んでおいても、読み込んだあとのスタックが同じになります。

|入力|答え|
|:-:|:-:|
|-2 -1 -1|Yes|
|-1 -2 -1|No|

どちらも、最初の`-`で積んでおいた値どうしが引き算され、2つ目の`-`でそこから2か1が引かれ、3つ目の`-`でさらに1か2が引かれます。引いた合計はどちらも3で、最後に1が積まれるので、スタックは同じになります。答えが違うのにスタックが同じなので、どう書いても区別できません。
ABC075でも、`-2 -2 -1`（答えは-1）と`-3 -1 -1`（答えは-3）が同じスタックになります。

# 残りの問題
最後に、この連載でまだ扱っていなかった、数を読み込むだけの問題を2つ紹介します。

[ABC042](https://atcoder.jp/contests/abc042/tasks/abc042_a)

```
[NO][YES]?**175=0rp
```

|入力|5 5 7|
|:-:|:-|

|出力|YES|
|:-:|:-|

3つの積が$5 \times 5 \times 7=175$かを調べます。$175=5^2 \times 7$なので、10以下の3つの数の積が175になるのは5、5、7の組だけです。積だけで正しく判定できます。

***

[ABC062](https://atcoder.jp/contests/abc062/tasks/abc062_a)

```
[Ar^101001010200r/A%]sa[No][Yes]?laxrlax=0rp
```

|入力|1 3|
|:-:|:-|

|出力|Yes|
|:-:|:-|

グループを0、1、2の番号で表し、$x$のグループの番号を$10^x$の位に書いた数101001010200を用意します。例えば$10^2$の位は2なので、2のグループの番号は2です。
aは、一番上の$x$をそのグループの番号にするマクロです。「Ar^」で$10^x$を求め、「101001010200r/」でその位までを取り出し、「A%」で一の位を取り出します。$x,y$の番号を求めて、等しいかを調べます。

# おわりに
この連載では、AtCoderのABCのA問題をdcで解く方法を紹介してきました。dcは計算が得意な一方で、文字列を扱うのは苦手です。入力をコードとして実行するという特徴をうまく使うと、解ける問題が増えることがあります。
